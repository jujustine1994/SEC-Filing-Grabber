## G2 + G7. 跨公司輸出改版

### G2. `Compare_Data` 最上方加「日曆季 ↔ 財季」對應表

CTH 確認的版面（比原提案多帶期末日，一格講完）：

```
             2024Q1              2024Q2              2024Q3        ...
AMD          FY2024Q1 (0330)     FY2024Q2 (0629)     FY2024Q3 (0928)
NVDA         FY2025Q1 (0428)     FY2025Q2 (0728)     FY2025Q3 (1027)
AVGO         FY2024Q2 (0505)     FY2024Q3 (0804)     FY2024Q4 (1103)
```

- 放在整張 `Compare_Data` 的**最上方**，在第一個指標區塊之前
- 下面的財務指標區塊**只給日曆季**，不重複財季
- **為什麼用對應表而不是「只寫每家公司的財年開始月份」**：對應表是逐期從實際期末日
  算出來的，公司哪一年改過財年，那一欄自己就會反映出來，**不需要任何例外處理**。
  寫「財年開始月份」只能寫一個值，公司改過財年就直接失效

**前置改動**：`comparison.ComparisonResult` 目前只留 `period_ends`，
`_aligned_labels()` 轉換完就把原本的財季標籤丟了。要多帶一個欄位：

```python
fiscal_labels: dict[str, dict[str, str]]   # {ticker: {日曆季: 財季}}
```

`build_comparison()` 在跑 `_aligned_labels()` 時順手把 `(aligned, 原label)` 存起來。

**注意**：`write_chart_sheets()` 用 `block_ranges` 定位資料列、用 `data_ws.max_column`
定寬度。最上方插入區塊會把所有列號往下推——`block_ranges` 是回傳值所以會自己跟著走，
但 `write_snapshot_sheets()` 也吃 `block_ranges`，要一起確認。**這裡要有測試釘住
「插入對應表之後，Snapshot 公式仍指到正確的列」**。

### G7. 加一張「說明」sheet（2026-08-22 CTH 追加 checkbox 需求）

CTH 明確說這張表未來會擴充，所以**要做成資料驅動**——一個

勾起來代表「這份檔案真的踩到這個狀況」。使用者不必讀完九條去猜哪條跟他有關。

版面：

| ✓ | 說明項目 | 內容 | 這份檔案的實際情況 |
|---|---|---|---|
| ✓ | 各公司財年結束月不同 | … | NVDA 1 月、AVGO 11 月、其餘 12 月 |

|   | Q4 為推算值 | … | （本檔無推算 Q4） |

**判定方式：**

| 條目 | 判定 |
|---|---|
| 時間軸＝日曆季、判準期中點 | 結構性，永遠勾 |
| 各公司財年結束月不同 | 由各公司期末日推出的結算月不只一種 |
| 同欄各公司期末日不同 | 任一欄的 `period_ends` 各公司不全等 |
| 期末結算日取最晚 | 同上（有差異才需要說明取哪個） |
| Q4 為推算值 | **需要 `comparison` 多帶一個旗標，目前沒有，要加** |
| 有缺值 | 任一格是 `None` |
| 期間早於 XBRL 強制申報 | 最早一欄的期末日早於 2011 |
| 單位、定義適用範圍 | 結構性，永遠勾 |

## G6. 抓不到的季度不要跳過，留一整欄空白

### CTH 的要求

現況欄位清單是「成功抓到什麼就放什麼」，某一季掛掉整欄消失，畫面上 25Q3 直接跳到 26Q1，
使用者與 AI 都看不出中間漏了一季。要改成**保留欄位、內容全空**，讓「有漏」看得見。

### 規格（2026-08-22 用 52 家實際資料定案）

**判定公式就是一行：**

```python
missing = round((next_period_end - this_period_end).days / _QUARTER_DAYS) - 1
```

`_QUARTER_DAYS = 91`（13 週 × 7 天，**要寫成具名常數並註明來源**，不是隨手取的數字）。

**用 52 家、1,482 對相鄰期間驗證過：**

```
<70 天                    1   0.1%
70-110（正常一季）      1413  95.3%
111-150                  16   1.1%
151-210（缺 1 季）        52   3.5%
211-300                   0   0.0%
>300                      0   0.0%
```

- 111~150 那 16 筆**全部是 COSTCO**——它的第四季是 16 週（112~119 天）。
  `round(112/91) = 1`，正確判為「沒缺」。**這就是為什麼不能用固定門檻（例如
  「>120 天算缺」），要用 round 除法**
- 151~210 那 52 筆都落在 182~189 天，`round(182/91) = 2` → 補 1 欄
- **實測沒有任何 >210 天的案例**，所以實務上不會連缺兩季
- 那 1 筆 <70 天是 SNOW 的 `2022-01-31 → 2022-01-31`（0 天，同一個期末日出現
  兩次）。`round(0/91) = 0`，規則自然不補——但那是**重複列**，要另開條目查

**配套：**

- **單一缺口最多補 4 欄**。實測沒有 >210 天的，真出現就是資料異常，
  不該讓程式無限生欄
- 只補在「最早抓到的那一季」與「最新」之間（CTH 已定）
- 缺欄的第 5 列期末日用 `_fiscal_period_end()` 反推年月

### 風險：中

## G8. 用「比較欄」當 fallback 補洞

### 背景（實測，不是推測）

CTH 問「為什麼 2009Q4 都沒資料」。直接原因：2009Q4 是合成 Q4，需要 Q1/Q2/Q3，
而 2009Q1 那份 10-Q 是純 HTML 沒有 XBRL（SEC 強制申報 2009-06 才對大型申報人上路）。

**但那一期的數字其實拿得到。** 10-Q 的 XBRL 除了當期還帶去年同期的比較欄，
實測 NVDA 2010-05-02 那份 10-Q：

```
cols = ['2010-05-02 (Q2)', '2009-04-26 (Q2)']
                            ↑ 2009 那一季就在第二欄，有 XBRL
```

`_current_q_col()` 只取第一欄，**比較欄整個丟掉**。

### CTH 決策

- 「拿新的一年去對照舊的一年，當作 **fallback**」
- 「看能不能套用到其他狀況」→ 做成**通用的補洞機制**，不要寫死成「只補 pre-XBRL」

### 規格

1. 新增 `_prior_q_cols(df)`：回傳當期以外的所有季度欄（現在 `_current_q_col()` 只回第一個）
2. 三個 `_build_*_table()` 各跑完之後，做一輪 **fallback pass**：
   - 對每個「模板列在某期是 `None`」的洞，找有沒有任何 filing 的比較欄涵蓋該期
   - 有就填進去，並記下這一格是 fallback 來源
3. **優先序鐵則：當期申報優先，比較欄只補洞，永遠不覆蓋已有的值**
   （CTH 確認）。重編（restatement）造成兩版不同時，以當期那版為準
4. 比較欄的欄名同樣**不能採信 `(Qn)`**，要走跟 D0-6 一樣的日期反推
   （`_col_to_quarter_label()` 現在已經是這樣，直接沿用即可）
5. 要不要在 Excel 上標示「這一格是從比較欄補的」——**動手前問 CTH**。
   傾向要標（資料來源不同，分析師應該知道），但會動到版面

### 備案（成本較高，先不做）

SEC Company Facts API（`https://data.sec.gov/api/xbrl/companyfacts/CIK##########.json`），
一次拿回該公司歷來所有 XBRL fact。edgartools 的 `company.get_facts()` 已經在用來
抓流通股數。補洞能力更強，但同一期間會有多個 `frame`／多次重編，取版本的問題更複雜。

### 測試要釘什麼

- 比較欄能補上當期缺的那一期
- **當期有值時，比較欄不覆蓋**（這條最重要，寫成明確的回歸測試）
- 比較欄的 `(Qn)` 標錯時仍算出正確的財季（沿用 D0-6 的日期反推）

### 驗收

重跑 NVDA / INTC / AMD，看 2009–2010 那幾期的缺漏數有沒有下降、2009Q4 能不能合成出來。
**同時要比對「原本有值的期間數字有沒有變」——一格都不該變。**

### 風險：高（改資料來源優先序，會影響所有既有期間）
