# 多語言（i18n）設計

> 2026-08-14 · 對應 `docs/TODO.md` E1
> 狀態：設計已與 CTH 逐段確認，待實作

## 目標

GUI 介面與 Excel 輸出的顯示文字支援四種語言：繁體中文、简体中文、English、日本語。
語言存在 `config.json`，重開程式生效。日後新增語言只需兩步，不碰功能程式碼。

## 不做的事

- **不動任何抓取邏輯、XBRL 解析、數值計算。** 這次只搬字串。
- **不即時切換介面。** 選完語言彈英文視窗問是否重啟。
- **`logs/app.log` 不切換語言**，永遠繁中。log 是給維護者除錯用的，跟著使用者語言變等於自廢。
- **`Data_Financials` 的 C 欄（Original Item）不翻譯。**（理由見下節）

## 一、哪些字要翻、哪些不能翻

### Excel 四張表的欄位慣例

改完之後四張表一致：**A 欄＝英文機器鍵（永不變）／B 欄＝譯文／C 欄＝補充（永不變）／D 欄起＝數據**。

| Sheet | A 欄 | B 欄 | C 欄 | 這次改什麼 |
|---|---|---|---|---|
| `Data_Financials(Q)/(Y)` | `Revenue` | `營業收入` | `Net sales` | 只有 B 欄換語言 |
| `Data_Ratios` | `營收 YoY (%)` | 空 | 算法文字 | **A 欄改英文**、B 欄從空變填譯文 |
| `Data_Meta` | 混中英 | — | — | **中文 concept 改英文機器鍵**，譯文另置 |
| `Data_Segments` | 軸名 | — | — | 軸名譯文（`axis_label`） |

**沒有任何欄位左右位移。** `Data_Financials` 的固定列位（Revenue 第 8 列、Cash 第 38 列、
Total Assets 第 51 列…）與 `_DATA_START_COL = 4` 完全不動，README「寫跨公司模板」章節的
三個保證全部維持，既有跨檔案公式不受影響。

### C 欄為什麼不翻

C 欄是**公司財報原文**，不是 XBRL tag，也不是固定集合。實測七家公司的 `Revenue` 列：

| 公司 | C 欄 | 公司 | C 欄 |
|---|---|---|---|
| AAPL | Net sales | META | Revenue |
| AVGO | Total net revenue | MSFT | Revenue |
| COHR | Revenues | NVDA | Revenue |
| PLTR | Revenue | | |

`Net Income` 列更極端：`Net Earnings Attributable to Coherent Corp.`（COHR）、
`Net income attributable to common stockholders`（PLTR）。這是開放集合，無法建對照表，
只能逐筆呼叫 AI 翻——違反本工具「零 AI API」的核心設計（README 第 21 行）。

更根本的理由：C 欄的用途就是拿去 10-Q 原文 `Ctrl+F` 核對。翻成中文就搜不到，功能歸零。

### `Data_Financials` 第 3–5 列要順手修

現在 A 欄是 `財季 Fiscal Quarter` 這種中英混排，違反「A 欄純英文機器鍵」的慣例。
改為 A 欄 `Fiscal Quarter` / `Calendar Quarter` / `Period End`，譯文移入 B 欄。

## 二、模組架構

### 新增檔案

```
src/i18n.py              核心：LANGUAGES 清單、set_lang()、t()、目前語言狀態
src/locales/__init__.py
src/locales/zh_tw.py     STRINGS: dict[str, str]
src/locales/zh_cn.py
src/locales/en.py
src/locales/ja.py
```

### `t(key)` 的查找與 fallback

```
目標語言 → 繁體中文 → key 本身
```

缺 key 絕不 raise、絕不回空字串。最壞情況畫面顯示 `gui.btn.run`，一眼看得出哪裡漏了。

### key 命名空間

| 前綴 | 用途 | 條數 |
|---|---|---|
| `gui.*` | GUI 介面文字（按鈕、標籤、對話框） | 238 |
| `acct.*` | 三表科目 B 欄（`zh_labels.py` 遷入） | 127 |
| `ratio.*` | `Data_Ratios` 列名與算法說明 | 37 |
| `xls.*` | Index sheet、Data_Meta 顯示名、Segments 軸名 | 24 |
| `err.*` | 會回傳到 GUI 的錯誤訊息（fetcher / writer / fiscal_input） | 25 |
| | **合計** | **~451** |

### `LANGUAGES` 清單

```python
LANGUAGES = [
    # (代號, 下拉選單顯示名, Excel 字型)
    ("zh_tw", "繁體中文", "微軟正黑體"),
    ("zh_cn", "简体中文", "Microsoft YaHei"),
    ("en",    "English",  "Calibri"),
    ("ja",    "日本語",   "Yu Gothic"),
]
```

三個欄位分別驅動：存進 `config.json` 的值、設定視窗下拉選單（**動態生成，非寫死**）、
`excel_formatter.FONT_NAME`（現在寫死「微軟正黑體」，日文假名顯示不全）。

### 新增語言的成本

1. 複製一份 locale 檔改譯文
2. `LANGUAGES` 加一行

下拉選單、Excel 字型、缺漏 key 檢查測試全部自動涵蓋。**不必碰 `main.py` 或任何功能程式碼。**

日後若要讓非工程師直接編譯譯文，`.py` 換 `.json` 只影響 `i18n.py` 的讀檔那幾行。
現階段用 `.py`：無讀檔錯誤處理、`grep` 找得到、import 期就會發現語法錯誤。

### `zh_labels.py` 的處理

**保留檔案、保留 `zh_label()` / `axis_label()` 簽名**，內部改為呼叫 `t("acct." + concept)`。
`excel_writer.py:28` 與 `segments.py:33` 的 import 一行都不必改。

## 三、語言選單與持久化

### 位置

「進階設定」popup 最上方獨立一列，在 SEC Identity 之上（`_build_settings_popup` 的
grid row 0，既有 frame 往下移一列）。

**不另開 tab**：主視窗高度鎖死 650px（見 `main.py.__init__` 的 geometry 註解），
log 顯示區已緊到剩個位數 px，多一列會把 log 擠到全隱形。語言屬「設一次不再動」，
與 Identity / API Key 同性質。

### 呈現

- 標籤固定英文 `Language:`，四語下皆不翻譯（CTH 指定）
- 選項用各語言自稱（`繁體中文` / `简体中文` / `English` / `日本語`），
  任何語言下都認得出來
- `ttk.Combobox`，`state="readonly"`，選項由 `LANGUAGES` 動態生成

### 儲存後的重啟提示

**僅當語言真的變更時**才彈窗（改 API Key 不觸發）。視窗全英文——此刻介面仍是舊語言、
使用者要的是新語言，用任一方都尷尬，英文最中立。

```
Language Changed
Restart the app to apply the new language.
Restart now?
        [ Restart ]   [ Later ]
```

- **Restart** → `subprocess.Popen([sys.executable, *sys.argv])` 起新行程後 `root.destroy()` 退出。
  不用 `os.execv`：Windows 上它會覆寫當前行程，tkinter 尚未釋放的視窗 handle 可能殘留
- **Later** → 不動作，下次啟動生效

### config schema

`config.py` 的 `DEFAULT_CONFIG` 新增 `"language": "zh_tw"`。既有 `config.json` 無此欄位時
由既有的 merge-with-defaults 機制自動補上，**舊設定檔零遷移**。

## 四、正確性保證

### 四道防線

**1. 語言檔 key 必須完全對齊**
測試取四個（日後 N 個）locale 的 key 集合比對，任一少一條即紅燈。新增語言時漏翻自動被抓。

**2. 程式碼不得再出現寫死的中文**
測試掃 `src/*.py`，用 `ast` 剔除 docstring 後，發現 CJK 字串字面即失敗並指出行號。
排除 `src/locales/`。**這條永久生效**，防止日後功能開發時又寫死中文而悄悄退化。

**3. Excel 輸出逐格比對（最重要）**
- 動手前先為 AAPL / NVDA / PLTR 存一份現有輸出當基準
- 改完設繁體中文重跑，**逐格必須完全相同**（含 A/B/C 欄文字、數值、格式）
- 再設英文跑一次，驗證：A 欄仍英文標準名、C 欄仍公司原文、數值零變動、僅 B 欄變英文

**4. 既有 652 條測試全綠**

### 預期要修改的既有測試（~40 條）

列名改英文後，以中文字面找列的斷言必須同步更新。**這是介面變更的必然結果，非破壞**：

| 檔案 | 約略條數 | 樣態 |
|---|---|---|
| `tests/test_ratios.py` | 20 | `_find(tbl, "毛利率")` → `_find(tbl, "Gross Margin")` |
| `tests/test_excel_formatter.py` | 15 | Index 表頭、Non-GAAP 指標名斷言 |
| `tests/test_fetcher_gaap.py` | 5 | `m.concepts.index("最新期間")` → 英文鍵 |

## 六、已知副作用（需 CTH 知悉）

1. **`Data_Ratios` 的 A 欄從中文變英文。** 若既有 Excel 公式用中文 `MATCH`
   （如 `MATCH("毛利率 (%)", ...)`），須改為英文（`"Gross Margin (%)"`）。
   單位後綴 `(%)` / `(x)` / `(days)` / `($)` **原封保留**——`excel_formatter.py:247`
   靠它決定數字格式且優先於所有關鍵字判斷，拿掉會讓 `DSO` 被當金額除以 1,000,000。
2. **`Data_Meta` 的 A 欄從中文變英文機器鍵。**
3. **`Data_Financials` 第 3–5 列的 A 欄從中英混排變純英文。**
   第 1 列與第 5 列的**值**（`FY2026Q1`、`2025-12-27`）不受影響，日常 `MATCH` 用的是那些。
4. **`Data_Financials` 的欄位與列位完全不變**，跨檔案公式無須任何修改。
