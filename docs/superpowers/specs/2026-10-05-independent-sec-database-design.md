# SEC 財報資料庫獨立保存設計

日期：2026-10-05。狀態：使用者已審閱並於對話中確認；尚未實作或搬遷。
改版前 checkpoint：`ebb0022`（保留既有 revenue tools、skill 與測試）。

## 目的與已確認需求

使用者要求資料庫離開程式專案，以資料庫名稱獨立保存；現有程式、GUI、CLI 與過夜腳本繼續更新同一份資料。正式資料不能被程式的快取清理功能刪除。動手前 commit，完成後更新 Markdown 文件。使用者已同意以上方向，並要求套用 Superpowers 重新檢視。

成功的定義：更換或刪除程式專案不影響資料庫；清理不碰正式資料；重新解析保留歷史內容；資料庫失聯不被誤判為空庫；搬遷前後財報內容完全一致。

不宣稱任何本機資料夾能防止管理員刪除、硬碟故障或惡意程式。防止程式誤刪與提供可還原副本，是本次可驗證的承諾。

## 現況與證據

- `src/filing_cache.py:cache_root()` 指向專案 `local_db/filing_cache`；環境變數 `SEC_LOCAL_DB_ROOT` 可覆寫。
- 實際盤點：215 個公司資料夾、14,417 份 accession JSON，全部檔案約 1.488 GiB。搬遷時重新盤點，不以此數字取代現場清單。
- `.gitignore` 排除 `local_db/`，Git checkpoint 不含資料庫。
- GUI `_clear_cache_ticker()` 無確認；`_clear_all_cache()` 有確認；兩者透過 `shutil.rmtree()` 刪除正式公司目錄。
- `save_filing()` 使用 `os.replace()` 覆寫同名 JSON；原子寫入不等於歷史保存。
- `load_filing()` 對 schema、CIK、parser version、必要表格有檢查。版本不符不刪檔，但舊檔不能直接採信。
- 自動清理只處理一小時以上的 `.tmp`。啟動器與打包清理並未清除正式財報。
- 更新名單目前在 AppData 的 `config.json`，公司更新狀態在 `_meta.json`。
- 除核心程式外，`scripts/check_fy_labels.py`、`scripts/classify_holes.py`、revenue 分析與 `skills/sec-revenue-breakdown/scripts/local_context.py` 等直接引用舊路徑，必須全面搜尋並調整。
- 文件記載 Google Drive 同步 `Documents/Code`。未核實新目的地的同步設定；不能把同步當作獨立可還原備份。

## 方案比較與選擇

| 方案 | 優點 | 限制 |
|---|---|---|
| 獨立 JSON 資料庫＋集中路徑與保存介面（採用） | 原檔能逐位元組搬遷；既有 builders 可延用；容易查驗 | 需自行管理歷史版本、連接身分與写入鎖 |
| 搬遷同時轉 SQLite | 交易與索引較集中 | 額外格式轉換與讀取改寫；本次目的不需要 |
| 僅改資料夾名稱／加 Windows 禁刪權限 | 改動少 | 留著刪除 API 與覆寫風險；權限可能阻擋既有原子寫入 |

採用第一種。保存格式不升 `SCHEMA_VERSION`，不因搬遷觸發 SEC 重抓。不在本次直接設定 Windows ACL。

## 位置、身分與連接

預設目的地：`C:/Users/CTH/Documents/SEC財報資料庫`。其他機器採用該使用者的 Documents 位置，不寫死 CTH；Windows 應使用 Known Folder 解析實際 Documents 位置。

```text
SEC財報資料庫/
  database.json                 格式、UUID、建立時間
  filings/<TICKER>/             目前財報 JSON 與既有公司 _meta/_sixk_probe
  history/<TICKER>/<accession>/  歷史財報內容，SHA-256 命名
  metadata/update_list.json     更新名單，含版本與資料庫 UUID
  metadata/migration-*.json     搬遷清單、驗證與完成紀錄
  staging/                     未完成的寫入與遷移清單
  snapshots/                   有日期與校驗清單的本機快照
```

保留公司 `_meta.json` 與 `_sixk_probe.json` 在公司目錄，避免本次額外改寫全部 metadata 呼叫點。可變管理資訊與不可丟棄的財報內容有不同保存規則。

新增集中資料庫模組，統一提供根路徑、身分驗證與正式／測試模式。App 設定新增 `database_path`、`database_id`；設定只保存連接資訊，財報與更新名單由資料庫保存。

有已登記的 path/ID 時，兩者必須匹配。路徑不存在、marker 無效、ID 不符或無權限時，顯示資料庫未連接並停止資料庫更新；不得建立替代空庫或轉回舊路徑。沒有設定時可以探索預設位置的有效 marker，再登記原有資料庫；不得默默初始化。

新建、搬遷、重新連接都是明確操作。GUI 提供選擇既有資料庫的入口，CLI 提供對等入口；選取後必須讀 marker 驗證，不以資料夾存在即判定成功。GUI 顯示資料庫位置與連接狀態。設定損毀須與單純首次安裝區別，不能任意接到另一庫。

環境變數原本供測試覆寫；正式資料庫覆寫同樣需要有效 marker。測試清理必須由隔離測試庫的明確身分允許，環境變數本身不是刪除授權。

## 正式資料保存與更新

GUI、CLI、過夜更新與分析工具共用集中路徑；保留 `filing_cache` 的讀取相容介面可降低 builder 改動，但其註解與介面用字改成永久資料庫。不要維護兩套正式路徑。

從正式產品移除單一／全部清除按鈕與破壞性入口。舊刪除 API 若暫時為測試保留，對正式庫必須拒絕，不能只是隱藏按鈕。從更新名單移除公司只停止更新，不刪財報。

財報新增／重新解析使用以下流程：

1. 在隔離 staging 寫入新內容，完成 JSON、accession、CIK、必要欄位驗證。
2. 同一財報的提交持有跨程序寫入鎖；GUI 與另一個 CLI 不能交錯提交。
3. 已有內容時，先把舊檔按 SHA-256 存入 history，核對內容一致。歷史檔已存在時核對，不覆寫。
4. history 建立或驗證失敗即拒絕提交，正式檔保持原狀。
5. 新檔原子切換為目前版本。若當前檔已損毀，保留原始位元組作為歷史後才修復。
6. 程序中斷後應留下舊版或完整新版，不得留下半份正式 JSON；歷史檔不自動清理。

寫入失敗必須反映在更新結果與 log，不可仍把該次資料庫更新宣告成功。維持單次報表是否可由已抓到的記憶體資料生成，與持久化成功分開回報。

管理狀態可原子更新；財報內容不可在沒有歷史保存的情況下覆寫。版本相同且內容相同不建立重複歷史副本。

套件／格式相容性檢查仍保留；舊解析版本不因搬遷被視為正確。顯示「已保存，但需重新解析」與來源 parser version；離線且不相容時說明原因，不靜默使用可能錯誤數字。歷史內容可供日後重新解析與追查。

更新名單由 `metadata/update_list.json` 唯一保存。搬遷時從舊設定匯入，包括尚無財報的 ticker；空名單也是有效狀態，不能誤觸舊設定再次匯入。AppData 舊欄位僅作一次遷移來源。

只清理 staging 中確認未使用且超過一小時的暫存檔；正式財報、history、snapshots 不做容量／到期清理。保留既有 `.tmp` 搬遷原始副本，不把它計為正式財報。

## 搬遷、驗證與回復

搬遷前停止 GUI/CLI 更新並建立遷移鎖。目的地須在專案目錄外，不能與來源相同或互相包含；不接受任意非空資料夾。遇到 reparse point／symlink 停止，不跨出來源範圍。

生成來源所有檔案的相對路徑、大小及 SHA-256；原樣複製到新庫，不修改財報 JSON。複製後逐檔核對，重新盤點來源並確認未在搬遷期間變更。缺檔、雜湊不符或磁碟滿均不得切換連接。

建立資料庫身分、更新名單、驗證報告，全部驗證成功後才登记連接。中斷重跑只能使用相符遷移清單接續，不能任意覆蓋目的地既有資料。

原 `local_db/filing_cache` 保留為搬遷前副本，實作腳本不得自動刪除。正式程式只使用已登記新庫，不双寫。舊版程式若仍執行會寫舊位置，因此文件要明示停止舊版，並透過舊庫中的醒目搬遷說明記錄新位置。

提供明確的快照建立／驗證／還原流程：快照包含財報、history、資料庫身分與更新名單；寫入暫停或取得一致性鎖，保存清單及校驗碼，失敗快照不能標成可還原。還原只能到新目的地，核對完成後明確連接，不覆蓋或刪除正在使用的庫。搬遷前舊庫副本不能冒稱長期備份。

本次交付本機快照與還原驗證能力；第二顆磁碟或獨立雲端目的地尚未由使用者指定，完成報告明確標為未配置。不得默默把新庫加入 Google Drive 同步或宣稱已防護磁碟故障。

## 修改範圍與驗收

- 核心：集中資料庫模組、`filing_cache.py`、`local_db.py`、`config.py`。
- 入口：GUI、CLI、過夜腳本及必要的四語系文案；資料庫斷線時能修復連接。
- 周邊：盤點／驗證／分析腳本與 revenue skill 的實際路徑使用。透過 repo 載入集中介面，避免把程式路徑當成資料庫位置。
- 文件：README、ARCHITECTURE、CLI、PACKAGING、CHANGELOG、local-db-runs、相關 skill 整合說明。歷史規格保留，添加被新設計取代的註記即可。
- 測試：路徑與 ID 不符、空庫與失聯區別、正式刪除拒絕、跨程序更新、歷史保存失敗、損毀舊檔、搬遷中斷／來源變更、更新名單一次匯入、快照還原、分析工具讀新路徑。
- 既有離線財報／segments 測試通過；選 AAPL、NVDA 比較搬遷前後產生的報表內容。搬遷不打 SEC、不耗費重抓時間。
- 實庫核對所有檔案 SHA-256，交付搬遷報告、實際路徑、測試結果與剩餘備份限制。

## 規格自查

本規格不把檔案不覆寫與管理狀態不能變更混為一談；不放寬 parser 正確性檢查；不把原庫保留或同磁碟快照當作異地備份。搬遷、修復連接及還原都有明確入口與失败行為；本次不加入 SQLite、完整 SEC 原文抓取或 OS 權限改造。
